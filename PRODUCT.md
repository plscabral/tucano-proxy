# Product

## Register

product

## Users

Developers and coding agents investigating their own HTTP/HTTPS applications. People may work exclusively in a terminal, use the local browser inspector, or retain the desktop app. Agents may run inside Maestri, Orca, an editor or an ordinary terminal; no host-specific integration is required to execute the CLI.

## Product Purpose

Tucano Proxy is the network-debugging product in the Tucano family. Its core must run without Tauri or a graphical session. CLI automation, interactive TUI, local web and desktop expose shared capture/session behavior rather than independent proxy implementations.

Success means capturing, inspecting, filtering, composing/replaying authorized requests, comparing responses, annotating and exporting evidence without requiring the web or desktop UI. The browser and terminal can observe the same session concurrently.

## Brand Personality

Professional, recognizable, precise. Preserve the existing Tucano Proxy artwork and violet identity. Use Oh My Pi's terminal ergonomics, adaptive theming and careful rendering as references, not its chat-centric layout.

## Anti-references

The user explicitly rejected a basic/MVP experience, raw scrolling logs as an inspector, a CLI wrapper that requires the desktop, and a terminal interface that forces users into the web for ordinary debugging. Avoid decorative banners on every automation command, arbitrary new brand colors and duplicate implementations per surface.

## Design Principles

1. Terminal inspection is a first-class human workflow; structured commands are the agent workflow.
2. Show observed state and actionable failures. Never imply capture readiness before listeners are ready.
3. Keep evidence shared and viewing state independent. Follow/scroll pause is not capture pause.
4. Preserve target application behavior; inspection limits must not truncate forwarded traffic.
5. Make access, trust changes and mutations explicit. Local traffic remains sensitive.
6. Build on the current desktop interface for web parity; adapt platform interactions, not the brand.

## Accessibility & Inclusion

Support light and dark terminal appearance, explicit override, NO_COLOR, Unicode and ASCII alternatives, terminal resizing, keyboard-only operation and text labels alongside semantic colors. No custom font is required. Images enhance the identity where supported but never gate operation. Web controls retain visible focus, accessible names and existing localization.
